# v0.5 美术与表现规范

本作沿用用户提供的中式地府手绘参考：青色天空与水面、旧纸、暖金与朱红建筑、墨线和鬼火。框色可以鲜明，但不把全屏改成高亮色块。主场景承担氛围，界面保留呼吸空间。

所有场景、人物、框、按钮、图标、阴影和特效必须来自正规素材来源或 `image_gen`。CSS、SVG、Canvas 和程序粒子不能代替美术资源。代码负责已有位图的排版、裁剪、等比缩放、移动及状态反馈，文字和数值独立渲染。

## 卡牌的四层资源

从 `game/content/cards.json` 的 `visual` 读取资源。完整卡面由四个独立位图层组成，文字另排，不把文字烘焙进插图。

| 层 | 内容 | 比例与处理 |
| --- | --- | --- |
| 框 | 标题带、边饰、规则纸面；插画窗口透明 | 主卡宽:高 **4:7**；整体等比显示 |
| 背景 | 风、雷、烟、火、符纹等抽象画面 | 宽:高 **3:4**；在画窗内等比 `cover` 裁切 |
| 图标 | 符箓、法器、兵器等透明主体 | 使用透明 PNG，通常正方形画布；`contain` 完整保留轮廓 |
| 费用 | 青蓝鬼火轮廓，数字独立置于焰心 | 正方形透明 PNG；放在左上角并允许超出卡框 |

费用、背景和主体不可合并为一张带文字的成品卡。牌名相对整张卡居中，不能因左侧费用标识挤偏；费用突出范围需要在扇形手牌最左端和详情中保留安全边距。

标题与规则纸面必须不透明，不应看到后面的手牌或场景。当前素材通过同位重复框层补足细微透明度；不能用整张卡的 `opacity` 表示费用不足。费用不足、未选中和拖拽都应保持卡面可读；只有离场表现副本可以渐隐。

## 四个视觉家族

| family | 标签与颜色 | 完整卡框 | 藏品小框 |
| --- | --- | --- | --- |
| `strike` | 攻伐 · 朱砂红 | `card-frame-vivid-strike` | `collection-frame-strike` |
| `ward` | 护身 · 青玉绿 | `card-frame-vivid-ward` | `collection-frame-ward` |
| `spirit` | 灵术 · 靛蓝 | `card-frame-vivid-spirit` | `collection-frame-spirit` |
| `oath` | 阴契 · 绛紫 | `card-frame-vivid-oath` | `collection-frame-oath` |

通常攻击使用红、护甲使用绿、资源与成长使用蓝、阴债使用紫；按牌的主要功能选择家族。机械类型 `attack/skill/power/status/curse` 与稀有度是独立字段，不从框色推导规则。能力可使用蓝或紫，群攻也不因全场目标改变颜色含义。

背景色应呼应家族，但仍包含笔触、明暗和抽象动势。不能将一个纯色矩形当作卡牌背景，也不再使用场景建筑等具象背景抢占主体。现有牌可以复用合适的背景与物件；复用不等于每张牌拥有独立新插图。

## 图鉴、牌堆与行囊

使用宽:高 **4:5** 的独立简洁小框，组成背包式网格，不把完整手牌缩小后塞进列表。每格保留费用、名称、类型、数量和足够大的主体图。

卡牌小框沿用该牌的家族色、原抽象背景与透明物件；升级版单独分组。0 费显示 `0`，不可打出显示 `—`，X 费显示 `X`。点击打开完整卡面；返回时保留筛选、滚动位置和焦点。

小框等比显示，背景在自己的画窗裁切，主体等比完整显示。不得为适配网格单独压扁框和费用图案。

## UI 切片与场景布局

按钮优先三切片：左右端帽保持自身比例，中段平铺填充。卷轴等面板使用九切片：四角不拉伸，边缘沿长轴平铺，中心纹理平铺。切片位置与源图对应关系记录在 `game/src/skin-data.js`；调整尺寸时先改布局，不拉伸整张边框。

- 场景图等比覆盖竖屏画布；竖屏之外只显示纯深色。
- 不为常驻 HUD、手牌与操作栏加整块遮景底板。
- 地图连线使用已有路径位图重复排布，不改为程序画线。
- 怪物、法器、头像与费用图使用等比缩放；需要统一视觉大小时用单一倍率，不分别改变宽和高。
- 对比原图检查边饰、符纸、圆章、建筑轮廓是否变形；不能只检查元素框是否适配屏幕。

## 怪物与受击反馈

怪物使用透明图像，脚下放置已有硬边圆形阴影的透视位图 `enemy-shadow-hard`。图像底部与地面锚点分开：怪物升高时阴影缩小、变浅，落下时变大、变深，始终贴地，不随怪物整体漂浮。

单怪至五怪保持稳定槽位，目标离场不会让剩余怪物突然换位。生命、意图和点击区域跟随实例 uid，不能依靠图片文件名识别目标。每种怪可配置 `artScale`，但不压缩图像比例。

受击时对已有怪物图施加短暂整体红色状态滤镜并轻微位移；不能生成另一张程序绘制的红色角色。群攻和多段规则可以逐次结算，视觉层允许节制地合并同类短脉冲，避免遮挡整个战场。

## 特效资源与参数

`game/content/visual-effects.json` 管理已有 PNG 的持续时间、缩放、旋转、位移、透明度与锚点。规则只发事件或选择特效 id，不直接操作动画。

| id | 资源 | 用途 |
| --- | --- | --- |
| `play` | `fx-burn` | 已打出／消耗卡的魂火离场 |
| `discard` | `fx-ash` | 回合末普通弃牌化灰 |
| `slash` | `fx-slash` | 斩击命中 |
| `fire` | `fx-fire` | 火焰命中 |
| `thunder` | `fx-thunder` | 雷击命中 |
| `curse` | `fx-curse` | 咒术与状态反馈 |
| `guard` | `fx-guard` | 获得护甲 |
| `soul` | `fx-soul` | 还愿、恢复及能力反馈 |
| `selfGuide` | `fx-self-guide` | 向下拖拽自身牌的蓝色底部引导 |

当前燃烧与化灰是生成位图叠加、卡牌副本缩放和渐隐，不是逐像素烧蚀着色器。自身引导同样使用生成位图，不能用 CSS 渐变替代。位图效果不得遮住可读数值或阻断合法目标输入；减少动态效果偏好应缩短运动。

## 新增或替换素材

1. 优先判断能否复用现有素材；需要新图时从正规来源获取或使用 `image_gen`，透明主体与特效应要求真实透明底。
2. 将最终 PNG 放入 `game/public/assets/`，名称稳定、语义清楚。不要让运行依赖下载目录、生成临时目录或绝对路径。
3. 更新 `game/public/assets/art-manifest.json`。记录 `filename`、用途、来源和提示词文件；外部素材附原始链接、许可及必要署名。
4. 在对应提示词记录中保留完整提示、参考信息、生成来源及必要的文件尺寸／哈希。派生裁剪记录 `derivedFrom`、`crop`；经用户授权的素材调整记录操作及原件。
5. 在源表或切片配置引用新资源，再运行内容、素材与比例检查。原件若仍是来源链证据应保留；完全被替换的无引用文件与过时代码归档到 `.local/temp/`。

当前特效提示记录为 `game/public/assets/fx-prompts.json`。程序只负责复制、裁剪和摆放这些有来源的资源；不能把无来源的程序绘图伪称为派生素材。

## 视觉验收

至少检查 390×844 与 320×568：四家族主牌、图鉴小牌、五张手牌、费用外伸、详情与选择面板、1–5 怪、长文案、低香火与不可打出牌。检查缺图、透明纸面、被裁费用、重叠按钮、横向溢出、压扁的端帽及模糊的缩放。

动态验收覆盖怪物升降与阴影同相、攻击红闪、不同命中特效、出牌燃烧、整手弃牌化灰、自身下拖提示，以及拖回取消后无残留效果。脚本比例检查只能发现几何问题，最终手感与画面仍需真实浏览器和手机试玩。
