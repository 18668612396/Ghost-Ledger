# 可视化配置工坊

独立工具目录为 `tools/content-editor/`。在仓库根运行 `npm run editor`，或进入该目录运行 `npm run dev`，打开终端打印的本地地址（默认 `http://127.0.0.1:4213/`）。启动、备份及目录职责见 [工具说明](../tools/content-editor/README.md)。

当前共用九张策划源表：卡牌、能力、怪物、遭遇、幕、事件、特效、法器和药物。文件均位于 `game/content/`；其中法器为 `relics.json`，药物为 `potions.json`。保存由同一编译器生成 `game/src/generated/content-data.js`，不能手改生成文件。

## 编辑范围

| 对象 | 常规可视化编辑 | 关联或高级编辑 |
| --- | --- | --- |
| 卡牌 | 名称、类型、费用、目标、规则、效果顺序、升级、美术素材 | 动态表达式、条件、触发与其他保留字段 |
| 怪物 | 类别、生命区间、立绘、行动效果、固定／序列／权重 AI | 行动条件、初始状态、触发与机制描述 |
| 幕 | 起始资源与牌组、内容池、奖励权重、地图楼层和限制 | 难度修正与额外配置 |
| 遭遇 | 权重、遭遇池、固定阵容、有限抽袋、组成移除 | 变体和随机槽位 JSON |
| 事件 | 描述、选项、效果、后续遭遇 | 条件表达式与其他字段 |
| 法器 | 名称、素材、触发时机、通用效果、次数限制、开场抽牌修正、出门行装 | 触发条件表达式及保留字段 |
| 药物 | 名称、素材、目标、使用场景、售价、通用效果 | 嵌套条件与其他效果字段 |
| 共享能力与特效 | 基础信息及现有数值 | 复用原源表结构的高级字段 |

各 JSON 区域必须先应用到草稿，保存按钮才会写入游戏源表。没有常规控件的字段会保留。新操作、新节点服务和模式入口仍是工程工作，工具不能用未知操作绕过正式校验。

JSON 面板未编辑时跟随表单最新数值；已编辑时保留文本，若同一字段又被表单修改则阻止应用旧值。还原读取当前草稿，而不是构造界面时的旧快照。多个未应用面板分别保留状态；所有待定内容处理后才能保存。效果数值和静态规则文案分别配置，需自行同步或使用现有动态占位符。

## 工作流程

从左侧搜索记录，在表单中修改，结合右侧预览查看结果。卡面可以切换基础与升级版；怪物意图、遭遇抽选和地图预览调用游戏现有规则，预览不推进游戏存档。地图可指定种子。

法器预览展示触发条件摘要，并通过实际规则计算“只持有此法器”的首战开局；胜利、还债等后续时机仍需在游戏中验证。药物预览在独立样例中执行配置的效果，显示使用前后数值和敌人状态。预览不消耗浏览器中的药物，也不保存游戏进度；涉及选牌时会提示仍需完成实战检查。若当前幕首层没有可直接进入的战斗，战斗样例会明确报错，其他配置内容仍保留。

法器与卡牌、怪物共用效果及触发规则。出门法器必须引用真实修行成就，全表恰有一件 `starter.unlockId:null` 的默认行装。敌方目标药物仅允许用于战斗，单体效果必须配置匹配的指定敌人目标。检查全部会拒绝失效引用、非法操作、目标与场景冲突以及缺失素材。

切换记录保留已应用草稿。查看变更摘要，执行检查全部，处理字段与引用错误后保存全部。保存前仍会再次检查磁盘版本；其他窗口或外部程序改动源表时，保留当前草稿并拒绝覆盖。先导出草稿，再重载并合并。

新增、复制、删除、导入先改变草稿。删除有确认并可撤销；源表仍被其他记录引用时不能强行保存。导出可选择当前记录、当前表或全部九表；导入对应 JSON 文件后会先展示影响范围。

当前运行格式为 `version:5 / ruleset:'config-v2'`。新局固定九表规则快照，修改源表后需刷新并新开夜巡体验新规则；恢复已有 v5 夜巡继续执行其快照。旧版夜巡不迁移、不执行，浏览器原始记录由保存层保留。工坊的源表备份与游戏进度备份分别管理。

地图总层数失焦时提交，末层首领、末前休息层及终段出现限制会同步相对位置。与其他固定节点冲突时保留原数据并提示，不静默覆盖。预览可限制显示规模以保持流畅；以正式全表校验结果为准。
