# 夜渡 · 配置工坊

本地可视化配置工具，独立放在 `tools/content-editor/`。与游戏共用源表、严格校验器和编译器，不建立另一套游戏规则；没有第三方运行依赖。

## 启动

需要 Node.js 20+。在仓库根目录执行：

```powershell
npm run editor
```

启动后打开 [配置工坊](http://127.0.0.1:4213/)。端口占用时执行 `npm run editor -- --port 4214`。也可进入本工具目录运行 `npm run dev`。服务仅监听本机回环地址；关闭终端或按 `Ctrl+C` 停止。

## 使用

1. 从左侧选择卡牌、怪物或关卡。关卡包含幕、遭遇和事件；共享能力与特效是辅助配置。
2. 搜索并选择记录，在表单中修改名称、数值、效果、行动、地图或素材。右侧预览使用已有素材和正式运行时。
3. 复杂表达式、条件、触发等可在对应 JSON 区域编辑；修改后先应用到草稿。整条记录也有高级 JSON 入口，未识别字段会保留。
4. 点击检查全部，处理字段和关联引用错误，再保存全部。保存的是所有已修改记录，切换条目不会自动写入源表。
5. 保存成功后，刷新游戏并新开夜巡体验新配置。继续已有夜巡仍使用其固定快照；新增幕还需在游戏模式入口中登记。

修改地图总层数，在离开输入框时提交；末层首领、末前休息层及靠近终点的出现上限会保持相对位置。目标楼层冲突时保留原配置并提示，仍需手动修正后通过校验。路线预览可切换种子，展示的是正式生成器的结果。

新增、复制、删除和导入先作用于草稿；最终写入受全表校验约束。不能删除仍被起始牌组、遭遇或其他记录引用的内容后强行保存。需要放弃修改时重新载入源表；也可导出 JSON 留存草稿。

干净的 JSON 面板会跟随表单数值更新。已编辑但未应用的 JSON 会保留文本；若同一字段又被表单修改，应用会提示冲突，先还原到当前草稿再编辑。规则文字是策划文本，改变效果数值时也要同步文案，或在高级字段中使用现有 `textValues` 动态占位符。

## 保存与恢复

- 源表位于仓库根下的 `game/content/*.json`；生成文件仍为 `game/src/generated/content-data.js`，不能手改。
- 保存前复用 `tools/compile-content.mjs` 的校验及 PNG 检查，在 `.local/temp/content-editor/` 生成候选文件。
- 实际写入前将变动源表的原始字节和旧生成文件备份到 `.local/temp/content-editor/backups/<时间与标识>/`，同时保存清单。无变化的表不重写。
- 写入失败会恢复已替换的文件；备份和候选资料继续保留在 `.local/`。需要人工恢复时停止编辑，按清单将备份放回对应源表后执行 `npm run content:check`。
- 编辑器会检查源表字节版本；其他窗口或程序修改文件后，旧草稿不能直接覆盖。先导出草稿，再重新载入并合并。
- 本地工具通过会话标识及同源请求限制写入，游戏开发服务和静态产物不提供编辑 API。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `server.mjs` | 本地页面、游戏素材与共享模块、编辑 API |
| `store.mjs` | 七表读取、校验、冲突检查、候选编译、备份与保存 |
| `public/app.js` | 列表、草稿、切换、导入导出、校验与保存流程 |
| `public/forms.js` | 卡牌、怪物与世界配置的结构化表单 |
| `public/previews.js` | 卡面、怪物、遭遇、事件与种子路线预览 |
| `public/styles.css` | 编辑器布局、控件与预览样式 |

本工具是配置编辑器，不提供素材生成、脚本编程或新机制解释。全新规则操作仍需扩展正式 schema、运行时与回归检查；数据预览不能代替正常冒险试玩和平衡验证。

复杂嵌套条件、触发器，以及遭遇的变体／槽位使用独立的 JSON 区域；固定阵容、抽袋和常用效果提供结构化操作。编辑器不会因为字段没有常规控件就将其删除。
